# eq-01 evidence

## Expected values and behaviour (2026-10-06, core 867ddd5)

| Vector | What | Exact |
|---|---|---|
| Q01 | 2x + 3 = 11 typed and stored | the equation reads 2×X+3=11 |
| Q02 | XEQ on it | stops for X (the Y line shows X?) |
| Q03 | X = 4: left minus right | 2 x 4 + 3 - 11 = 0 |
| Q04 | X = 5 | 2 x 5 + 3 - 11 = 2 |
| Q05 | SOLVE X | 4, stored in X |

## Sources

- The equation's keys, its bar and XEQ's left-minus-right: abacus-firmware units 014 (M01, M09-M12),
  015 and 020 (the soft keys as the equation bar: ◀ ▶ ( ) = SPC REG while typing).
- Evaluating leaves Equation mode, so SOLVE needs the equation shown again: observed on the device
  path (keyrun --sequence: after XEQ's R/S the status band loses EQN, and SOLVE then shows SELECT
  FN); the lesson's keys show it again with EQN each time, and the student run confirms.
- 2X (no x) is a syntax error when evaluated, in 33s and 35s mode (probed; STU will allow implied
  multiplication after unit 031, abacus decision 53).

## The checker grew for this lesson

- keyrun resolves soft keys by the labels the screen shows (app_ui), so the equation bar's = and
  ( ) are pressable by name; this also ends two documented false reds (CLR ALL?'s Y, CONST's later
  pages).
- keyrun reports the Y line; `kind="prompt"` matches a prompt on either line (XEQ's X? is on Y), and
  `kind="eqn"` an equation on X.
- Controls (eq-01): a misquoted equation, a misquoted prompt, a bar key that does not exist, and a
  second check without showing the equation again, all red.

## Checks

`make check`: 10/10 vectors in 33s and 35s, from a fresh and a used core; 11 keys blocks; 11 quotes
(values, the equation, the prompt, the EQN annunciator, the SYNTAX ERROR message), each on the
device, and again for a student working through in order.
